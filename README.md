# AI 协作与复盘 Coach

面向大学 AI 素养实践课的中文 Coach Skill。用于作品构思、路线决策、关键技术验证、跨工具排错与证据复盘，支持图片、视频、音乐与播客、前端应用、小游戏、Skill 和智能体等项目。

当前版本：**v0.3.0**（2026-10-28 更新）。默认分支 `main` 为当前公开版本；核对更新时同时检查 `SKILL.md` 版本与实际文件／提交标识，不只比较版本号。

## 一句话安装

复制下面的固定仓库链接，粘贴到支持从 GitHub 安装 Skill 的大模型或 Agent 中，并发送：

> 请帮我安装这个 Skill：https://github.com/yiyi1108/ai-collaboration-coach

本仓库的 `SKILL.md` 位于根目录，相关 `references`、`assets`、`scripts` 和 `agents` 均使用标准相对路径，便于支持 GitHub Skill 安装的工具直接识别。

> 平台必须具备读取 GitHub 仓库并安装 Skill 的能力；普通聊天模型如果没有文件安装权限，无法仅靠提示语完成安装。此时请使用下方 ZIP 安装包，或使用 `PORTABLE_PROMPT_ZH.md` 作为降级方案。

## 已安装用户检查更新

已安装 v0.2.0 或其他旧版时，优先更新现有 Skill，不必先卸载，也不要重复安装成两个同名 Skill。可复制：

> 请检查并更新我已安装的 ai-collaboration-coach：https://github.com/yiyi1108/ai-collaboration-coach
>
> 请核对已安装版本与仓库默认分支 main 的最新版本；如有更新，更新完整 Skill，包括相关规范、Word 模板及脚本，不要只替换 SKILL.md，也不要重复安装。
>
> 保留我的作品、聊天记录和其他个人文件；如果发现我自行修改过 Skill 文件，请先说明冲突并征求确认。
>
> 完成后，请重新读取已安装文件，告诉我更新前后的版本、核对依据，以及是否需要重新加载或开启新对话。若当前平台不能执行更新，请明确说明，并提供适合该平台的手动更新步骤，不要仅回复“已更新”。

更新应使用同一次下载或同一提交中的整套文件，避免新规则配旧模板；不要仅把新版叠加到旧目录而留下已停用规则。平台不支持对话更新时，先备份自行修改的内容，再按其技能管理界面导入完整新版并替换或停用旧副本。学生作品与聊天记录不属于可清理的 Skill 文件。安装完成不等于当前对话已重新加载，应按平台实际反馈确认。

## ZIP 安装

- [下载当前版本完整 ZIP（main）](https://github.com/yiyi1108/ai-collaboration-coach/archive/refs/heads/main.zip)
- [查看历史发布版本](https://github.com/yiyi1108/ai-collaboration-coach/releases)（历史 Release 不一定与 main 同步，请以本页当前版本为准）

解压后将顶层文件夹 `ai-collaboration-coach-main` 重命名为 `ai-collaboration-coach`，保留完整内容，再按平台要求导入文件夹；支持此类 ZIP 的平台可直接导入。若平台要求特定 ZIP 目录结构，按其要求重新压缩，不假定所有平台接受同一种包结构。入口文件是根目录的 `SKILL.md`，不要只复制该文件。

## 直接开始

- “我没想法，喜欢摄影和推理，请帮我找一个适合小规模尝试的方向。”
- “我已经确定做这个，请先帮我处理最关键的实现问题。”
- “这是另一工具给的结果，与预期有这些差别，请帮我判断下一步。”
- “我们想法已经比较清楚，请整理完整的作品创作方案。”
- “项目暂时到这里，请帮我们整理 AI 工具使用说明。”

作品创作方案默认使用六部分 Word 模板；复盘的正式主交付是固定 Word 模板的“AI 工具使用说明”，HTML 可视化简介版在 Word 核对、优化后按需生成。AI 主力整理已有过程，学生补充不可见信息、确认判断与反思，不编造经历或测试。当前平台不能生成文件时，明确降级为对应内容，不冒称已生成 Word。

## v0.3.0 的主要变化

- 完善 A／B 轨领域方法、作品构思与类目化执行方案，按实际问题选方法，不机械运行全部提示词。
- 加入作品创作方案与 AI 工具使用说明两份 Word 模板；统一跨窗口续接和便携版规则，减少重复填写。
- 报告流程改为回顾预填、补缺访谈、AI 提炼制作、学生核对修改；HTML 保持固定结构，仅提取已确认 Word 内容。
- 修复报告检查器对空正文、损坏文件误报通过的问题，补充维护用回归测试。

## 核心结构

```text
SKILL.md                  # Skill 入口与运行规则
PORTABLE_PROMPT_ZH.md     # 不支持 Skill 安装时的便携降级提示
agents/openai.yaml        # Agent 展示与调用元数据
references/               # 构思、验证、领域方法、报告等按需参考
assets/                   # 两份 Word 模板、HTML 模板、图标与字体资源
scripts/check_report.py   # 报告交付检查脚本
scripts/test_check_report.py # 维护用回归测试，不是学生任务
licenses/                 # 第三方资源许可
```

## 验证边界

已完成结构、引用与资源检查、报告检查器的 19 项回归测试，以及部分独立模拟情境检查。Word 模板随包提供；模板结构检查和模拟行为不能证明真实教学效果，也不等于每个平台都能完成安装、Word 生成或媒体制作。跨平台兼容性和课堂效果仍需实际验证。

安装成功至少应能读取根目录 `SKILL.md`、所需 references 及两份 Word 模板，且文件来自同一版本。Python 3 仅用于运行报告检查脚本，不是所有辅导任务的前提；Word 制作、联网、媒体生成、代码执行等依赖宿主实际能力。Notion 案例库也需要另行授权，安装 Skill 不会自动获得访问权限。

维护者可运行 `python3 scripts/test_check_report.py`；检查具体报告可运行 `python3 scripts/check_report.py --docx 报告.docx`，需要时追加 `--html 报告.html`。检查器只做基础结构和占位检查，不验证内容真实性、反思深度或视觉质量。
