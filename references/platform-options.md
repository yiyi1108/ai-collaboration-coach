# 平台与工具路线：按能力选择，不按品牌预设

## 1. 先识别任务与环境
区分当前对话环境、实际执行工具、已有账号与资源、已尝试方案。已知信息不重复问；只有差异影响下一步才询问。
识别能力类型：文本推理、图像生成/编辑、视频生成、音频、代码运行、浏览器、文件处理、数据接口、发布。不能因为某模型能描述操作，就认定当前入口可执行。
当前能力足够时直接推进，避免不必要搬运；学生已在用某工具时不重复“推荐去用”，但可提供相关功能说明和教程。

## 2. 决策需要什么依据
可能变化的功能、输入限制、接口、价格、权限与发布条件查官方一手资料；记录影响本任务的条件，不做无关产品大全。
查不到则如实说未核实；给不依赖该能力的替代，或设计可逆测试。只有当前工具清单、配置与真实结果才能说明本会话的可用性；官网支持也可能不适用于当前账号/入口。

## 3. 路线比较
按目标控制力、输入输出兼容性、能否修改、资源/时间、隐私与权限、交付方式比较。给推荐及原因，不把所有选择甩回学生。
- 创意与脚本可用通用模型；实际生成需要相应媒体能力，二者可在一个环境或分开完成。
- 小前端工具可直接生成并运行；模型接口、服务端、账号与部署只按功能增加。
- 现有成品/模板/技能/智能体可作为可选起点，先看真实输入、输出、工具依赖及权限，再决定复用、组合、改造、自建或不用。
- 学生没想法不等于必须套现成案例；使用新工具本身也不是创新。

## 4. 跨工具交接
写明每一步传什么：素材、比例/格式、提示词、参数、代码/数据、错误和不变要求。只带必要内容，不能默认上传私人材料。
相同提示词不保证跨模型相同效果；平台特定参数不能生搬。用真实目标小样验证兼容性，保留有效基线。

## 5. 能力缺失时的降级
无联网：使用已提供资料，注明时效与未核实部分；不冒充实时调研。
无文件工具：提供可复制文本或源码及保存方法；不声称已经生成可下载文件。
无代码执行/媒体生成：提供完整输入、操作与判据，邀请带回结果；不称已运行。
无持久记忆/外部可见性：依靠简报与材料续接，不承诺追踪。
无Skill安装支持：使用便携核心及必要附件，不承诺与完整包一致。
模板或参考不可读取：说明具体缺失，继续能做的部分，不凭印象声称复现。
