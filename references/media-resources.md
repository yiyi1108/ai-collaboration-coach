# 图片／视频／音乐操作文档索引

用途：A轨作品需要操作、参考、关键技术判断或排错时，Coach按**创作链路、实际问题、实际生成平台与模型**选读。这里是指引读哪份、读什么的索引，不是要求把全部文档或链接一次性交给学生。

核读说明：下列“已核读要点”来自2026-10-26整理时可读取的官方页面，仅用于快速定位；页面、模型和参数会更新，临用仍核对当前版本。SeedMusic手册本轮两次读取均失败，故只保留入口，不写未核实的功能与参数。读取失败不等于链接失效，也不证明能力不存在。

## 1. 先确定读什么：四条读取原则

1. **沿创作链路向前看一步**：视频若依赖生成人物、场景、道具、首尾帧等资产，在定路线和首次生成前同时查图片文档；图片负责资产视觉质量，视频负责参考输入、动作、运镜、声音和镜头生成。不要等视频失败后才发现资产本身不成立。
2. **按实际执行端选文档**：当前对话模型不等于实际生成平台。在豆包直接生成，查Seedream／Seedance；在其他窗口对话但去即梦生成，查即梦对应模型；在可灵生成，查Kling；通过方舟API调用，查方舟对应模型教程。对话模型可以协助拆解和写提示词，但不因此获得执行端的能力。
3. **按问题读相关章节**：先查会改变路线、成本或可行性的能力，再查当前操作。通常给学生一至两个最相关入口并说明阅读重点，不默认全文通读，不机械发送整组链接。
4. **通用方法与平台能力分开**：自然语言描述、参考分工、资产前置、代表测试等可迁移；参考数量、时长、参数、按钮、音频／方言支持和图层能力不可跨模型混写。文档说明能力不等于本任务已成功，最终以实际生成和试听／观看验收。

## 5. 按创作链路组合读取

| 当前任务 | Coach内部按需读取 | 给学生的主要帮助 |
|---|---|---|
| 从零做连续视频 | 图片§1＋视频§2；图片资产文档＋当前视频模型文档 | 先定分镜和资产职责，过图片关，再测代表镜头与声音；不是只给一份视频提示词 |
| 已有图片做视频 | 图片§1.7＋视频§2.4—2.6；按图片缺陷决定是否回查图片文档 | 先判断图片是否可做资产，再写动作、运镜和参考关系 |
| 台词／方言驱动视频 | 视频§2.2、§2.9；当前视频模型的音频与提示词文档 | 先做含专名、方言词和代表语气的短样段，分别人工验收文本、口音、音色、口型和同步 |
| 图片局部修改 | 图片§1.7；当前图片模型的精准编辑文档 | 说清改哪里、改成什么、保留什么；优先局部编辑，不整图重抽 |
| 原创歌曲／配乐 | 音频§3；音乐文档可读时选相关章节 | 先做代表段试听，核对用途、结构、歌词／配器和授权，不把配音问题混进作曲 |
| 模型尚不明确 | 先确认实际生成平台与模型，再读对应文档 | 可以给通用准备清单，但不提前承诺某模型专有功能 |

## 7. 证据边界与表达方式

- 不沿用“最优”“万能衔接”“同seed一致性85%”“一晚上做完”等断言，不编造成功率、成本、授权或平台能力。
- 已读正文时才概括具体要点；未读到时说“这是参考入口，我尚未读到相关章节”，不能虚构章节、参数或保证。
- 教程提供方法依据，案例提供可观察线索，代表测试决定是否适合当前任务。给学生建议时讲清**问题本质、为什么这样做、现在怎么做、做不到时的替代与后续路径**。
- 参考音频、图片、视频、音乐和真人声音需确认授权；不克隆或冒用真实个人声音，不把生成内容包装成真实记录。
